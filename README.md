# Telegram 投稿机器人

Python 3.12 + aiogram 3 + SQLite，使用 Docker Compose 部署，以长轮询方式运行，不需要公网 HTTPS。
支持 **Linux amd64 和 arm64**，例如普通 VPS、Oracle ARM、树莓派 4/5。

## 功能

- **投稿**：支持文字、图片、视频、GIF、文件、音频、语音，以及多图/多视频相册（media group 会自动合并成一条投稿）
- **格式原样保留**：保存的是 Telegram 原始的文字和格式标记（entities），不经过 HTML 转换，发布时原样带回去。超链接、粗体/斜体、引用、剧透文字、代码、日期时间、emoji 都不会变；用户设置的“关闭链接预览”“说明文字显示在媒体上方”“媒体剧透”也会保留。自定义 emoji 见下方“已知限制”
- **修改稿件**：管理员审核时可以用 `/edit` 修改。投稿人在审核结果出来之前也能修改：直接用 Telegram 自带的“编辑”改原消息（连图片都能换），或者用 `/edit`。新内容的格式同样原样保留，原稿会另外保存。修改后审核群会收到新的预览，控制消息上会标注“✏️ 已修改（谁，何时）”
- **署名 / 匿名**：用户发送内容后自己选择。署名的帖子附上投稿人链接，匿名的帖子附上“匿名投稿”（落款文案可在 `.env` 中配置）。无论哪种方式，管理员在审核群里都能看到真实投稿人
- **审核群操作**：可以立即发布、定时发布、拒绝、封禁投稿人；也可以用命令 `/no`、`/ban` 并附上自定义理由
- **剧透遮罩**：发布前可以给图片、视频、GIF 打上 Telegram 的 spoiler 遮罩
- **静音发送**：审核时可以逐条切换 🔔/🔕。打开后，频道订阅者收到的是无声通知（`disable_notification`），适合深夜或刷屏时段。定时发布也会沿用这个设置；新投稿的默认值由 `DEFAULT_SILENT` 决定
- **定时发布**：提供 +1h、+3h 和预设时间点的快捷按钮，也可以自定义时间（`20:30`、`10-20 09:00`、`2026-10-20 09:00`、`+90m`、`+2h`）。定时任务存在数据库里，重启后不会丢失
- **审核统计提醒**：按设定间隔在审核群发送统计消息，格式如下。每次审核操作后会就地刷新这条消息；发送新提醒时会删除上一条，群里始终只保留一条
  ```
  接受 0 拒绝 0 待审核 4
  通过率: 0.00% 审核率: 0.00%
  #审核统计 [更新于 16:03:10]
  ```
  - 通过率 = 接受 / (接受 + 拒绝)
  - 审核率 = (接受 + 拒绝) / (接受 + 拒绝 + 待审核)
  - `STATS_SCOPE=today` 时，“接受”和“拒绝”只统计当天审核的投稿；“待审核”始终是当前全部积压的数量
- **投稿人活跃度**：`/active [天数]` 列出投稿人排行，包括投稿数、通过数、通过率、匿名数、活跃天数和最近投稿时间；`/user <ID>` 查看单个投稿人；用户自己可以用 `/me` 查看
- **拒绝与封禁**：拒绝理由会发给投稿人，也会显示在控制消息上。封禁用户时，会**自动拒绝他所有未处理的来稿**（待审核、已排定时、发布失败的都算），未提交的草稿直接作废，并只给他发一条通知，说明理由和被拒的投稿编号。被封禁的用户再投稿时，会看到封禁理由
- **防滥用**：每人同时最多保留 N 条未处理投稿
- **彩色按钮**：使用 Bot API 的按钮 `style`。🟩 绿色：发布、重试；🟦 蓝色：署名/匿名、定时、已开启的开关；🟥 红色：拒绝、封禁；其余按钮保持默认样式。不支持按钮颜色的旧版客户端会按默认样式显示，功能不受影响

## 流程

```
用户私聊发内容 ─► 选择 署名/匿名 ─► 审核群：预览（即频道最终效果）+ 控制消息
                                              │
          ┌──────────────┬───────────────┬────┴─────────┐
   剧透 / 静音开关     立即发布        定时发布        拒绝 / 封禁
                         │               │               │
                         ▼               ▼               ▼
                    频道 + 通知用户   到点发布 + 通知   通知用户
```

## 部署

1. 准备机器人账号和聊天
   - 在 @BotFather 创建机器人，拿到 token。隐私模式（privacy mode）保持默认开启即可
   - 把机器人设为**频道管理员**，并给它“发布消息”权限
   - 把机器人拉进**审核群**，普通成员身份就够了：机器人删除自己 48 小时内发的旧统计消息，不需要管理员权限
   - 获取审核群 ID：把 @RawDataBot 拉进群看一眼，或者看机器人日志。群 ID 是 `-100` 开头的数字

2. 配置并启动
   ```bash
   cp .env.example .env    # 填写 BOT_TOKEN / CHANNEL_ID / REVIEW_CHAT_ID
   docker compose up -d --build
   docker compose logs -f
   ```

3. 更新代码后重新构建
   ```bash
   docker compose up -d --build
   ```

4. 备份：数据库位于 `bot-data` 卷中的 `/app/data/bot.db`
   ```bash
   docker compose cp bot:/app/data/bot.db ./backup-$(date +%F).db
   ```

## 本地运行（不用 Docker）

需要 Python 3.10 以上（macOS 自带的 3.9 不够），可以用 `brew install python@3.12` 安装。

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env                      # 填写测试机器人的 token、频道和审核群 ID
set -a; source .env; set +a
DB_PATH=./data/bot.db .venv/bin/python -m bot
```

`DB_PATH` 要改成本地路径：默认的 `/app/data` 是容器里的路径。启动前先建好 `data` 目录（`mkdir -p data`）。

- **代理**：在 `.env` 里设置 `PROXY=socks5://127.0.0.1:7890`，`http://` 也可以。在 Docker 里运行时，`127.0.0.1` 指的是容器自己，要访问宿主机上的代理，请填 `host.docker.internal`（Docker Desktop）或宿主机的局域网 IP
- **同一个 token 同一时间只能有一个进程在运行**，否则会出现 `Conflict: terminated by other getUpdates request`。本地测试请用单独的测试机器人
- **自建 Bot API 服务器**：设置 `TELEGRAM_API_URL`，可以突破官方 API 的 20MB 下载 / 50MB 上传限制

## 测试

```bash
.venv/bin/python tests/test_entities.py   # 格式偏移计算（UTF-16）单元测试，瞬间完成
.venv/bin/python tests/live_test.py       # 端到端测试，约 1 分钟
```

这个测试不需要真实的 token，也不需要联网。它会在本地启动一个模拟的 Telegram Bot API 服务器，让真实的 `python -m bot` 进程连上它，然后走一遍完整流程：投稿、相册合并、按钮颜色、剧透 + 静音（检查实际发出的 HTTP 参数）、自定义定时并由后台调度器真实发布、`/no`、`/ban` 自动拒绝来稿、格式保真（逐个核对实际发出的 entities 偏移，以及频道拒收自定义 emoji 时的自动降级）、`/edit` 修改并发布，以及每分钟一次的审核统计提醒。全程大约 1 分钟。

## 多架构（amd64 / arm64）

基础镜像 `python:3.12-slim-bookworm` 本身就是多架构镜像，所有 Python 依赖在 amd64 和 arm64 上也都有预编译 wheel，构建时不需要编译器。所以有三种用法：

1. **直接在服务器上构建（最简单）**：在哪台机器上执行 `docker compose up -d --build`，就得到那台机器对应架构的镜像，不需要额外配置

2. **在一台机器上同时构建两种架构，推送到镜像仓库**
   ```bash
   docker login ghcr.io
   scripts/build-multiarch.sh ghcr.io/<你>/tg-submit-bot:latest
   ```
   然后在各台服务器的 `.env` 里设置 `IMAGE=ghcr.io/<你>/tg-submit-bot:latest`，再执行：
   ```bash
   docker compose pull && docker compose up -d --no-build
   ```

3. **GitHub Actions**：仓库推送到 GitHub 后，`.github/workflows/docker.yml` 会在每次推送到 main 或打 `v*` 标签时，自动构建 amd64 + arm64 镜像并发布到 `ghcr.io/<owner>/tg-submit-bot`。拉取方式同第 2 种

## 审核群命令

| 命令 | 说明 |
|---|---|
| `/stats` | 立即发送一条最新的审核统计 |
| `/queue` | 查看定时发布队列 |
| `/active [天数]` | 投稿人活跃度排行，默认统计 30 天 |
| `/user <用户ID>` | 查看某位投稿人的统计（用户 ID 显示在控制消息里） |
| `/no [理由]` | **回复**某条投稿的预览或控制消息使用：拒绝这条投稿，理由会发给投稿人 |
| `/no <投稿编号> [理由]` | 不回复消息时用编号指定，`12` 和 `#12` 都可以 |
| `/ban [理由]` | **回复**某条投稿使用：封禁投稿人，并自动拒绝他所有未处理的来稿 |
| `/ban <用户ID> [理由]` / `/ban #<投稿编号> [理由]` | 不回复消息时指定用户。用户ID 可以是从没投过稿的人，用来预先封禁 |
| `/unban <用户ID>` | 解除封禁，会通知对方。也可以回复他的投稿后直接发 `/unban` |

示例：回复某张投稿图片，发送 `/no 与已有内容重复`；回复某条控制消息，发送 `/ban 发广告`。

### 修改稿件

| 命令 | 说明 |
|---|---|
| `/edit 新内容` | **回复**某条投稿使用：文字投稿替换正文，图片/视频/文件投稿替换说明文字（相册改的是带说明文字的那一张）。新内容里的超链接、粗体、emoji 等格式全部保留 |
| `/edit` | 不带内容：机器人把这条投稿当前的文字（带格式）发出来。你复制它，改完后再用 `/edit 新内容` 回复投稿即可，原有格式不会丢 |
| `/edit <投稿编号> 新内容` | 不回复消息时，用编号指定 |

修改后，机器人会在审核群重新发一份预览，内容就是频道里最终会显示的样子。管理员可以修改待审核、已排定时、发布失败的投稿；已发布或已拒绝的不能修改。

### 投稿人修改

投稿人在**审核结果出来之前**（还没提交的草稿、待审核的投稿）可以自己修改：

- **直接编辑原消息**：在私聊里长按自己发出的投稿，选择“编辑”，修改文字、格式，甚至换一张图都可以。机器人会自动同步，并回复“已更新”
- **`/edit 新内容`**：回复自己的投稿，或回复机器人关于这条投稿的提示消息。如果只有一条待审核的投稿，不回复也可以。多条时用 `/edit #编号 新内容` 指定
- **`/edit`**（不带内容）：机器人把当前内容发给你，方便复制后修改

待审核的投稿被修改后，审核群会收到新的预览，控制消息上会标注“✏️ 已修改（投稿人 xxx）”。投稿一旦通过、被拒绝或已发布，投稿人就不能再修改，机器人会说明原因。

控制消息上的 ❌ 拒绝 和 🚫 封禁投稿人 按钮，效果分别等同于不带理由的 `/no` 和 `/ban`。

审核群里的任何成员都可以审核，所以审核群只拉管理员进去。

## 项目结构

```
bot/
  __main__.py      启动、注册命令、长轮询
  config.py        环境变量
  db.py            SQLite 表结构与查询（状态流转是原子操作，防止重复发布）
  core.py          业务核心：投稿、审核、发布、定时调度、统计提醒
  render.py        发送内容（单条 / 相册、落款、剧透）以及各类文案
  entities.py      格式（entities）处理：UTF-16 偏移、去掉命令前缀、拼接落款
  keyboards.py     内联按钮
  album.py         相册收集
  timeutil.py      时间解析与格式化
scripts/build-multiarch.sh   buildx 多架构构建并推送
tests/live_test.py           模拟 Bot API + 真实进程的端到端测试
.github/workflows/docker.yml CI 多架构镜像
  handlers/
    user.py        私聊（投稿、/me）
    review.py      审核群（按钮、命令、自定义时间输入）
```

## 已知限制

- **自定义 emoji（会员表情）**：Telegram 只允许购买了 Fragment 用户名的机器人往频道发自定义 emoji。如果频道拒收，机器人会自动去掉自定义 emoji 重发，这些位置会显示成对应的普通 emoji，其余格式不受影响。审核群里的预览能否显示自定义 emoji，取决于机器人的创建者是否开通了 Telegram Premium
- 相册的说明文字加上落款后不能超过 1024 字，文字投稿不能超过 4096 字；超出时 Telegram 会返回错误，投稿会被标记为“发布失败”，管理员可以修改设置后重试或拒绝
- GIF 无法放进相册，Telegram 本身也不允许，所以用户发多个 GIF 时会变成多条投稿
- 自定义时间的输入状态保存在内存里，如果机器人在等待管理员输入时重启，需要重新点一次“自定义时间”
- 如果机器人在发布过程中被强制终止，重启后这条投稿会被标为“发布失败”，请先去频道确认是否已经发出，再决定是否重试
